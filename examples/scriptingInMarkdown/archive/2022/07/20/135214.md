[Joseph Zitt](https://github.com/scripting/reallysimple/discussions/6#discussioncomment-3187614): "It's very cool that you're supporting Markdown -- but which Markdown are you using?"

This of course is a great question. I answered it, the way all Markdown questions are answered.

Of course as you know there is no One True Markdown.

The approach we all take with Markdown text is to stay within a reasonable subset of the syntax, and hope for the best. ;-)

I go by this [cheat sheet](https://www.markdownguide.org/cheat-sheet/), which I keep in an icon in the chrome of my browser, easy to reach for. And it seems to work.

Re the Markdown processors I use --

*   On the client side -- I use [something](http://fargo.io/code/markdownConverter.js) called MarkdownCoverter, which I downloaded many years ago. I seem to recall it's the one that StackExchange uses, so I figured it's got to be pretty good. In all the years I've been using it there haven't been any complaints as far as I know.
    
*   On the server side -- I use [markd](https://www.npmjs.com/package/marked). I don't recall how I decided to use this one, but it has also served me well.
    

As I understand it Gruber likes the way it has evolved.

The shit does kind of hit the fan when it comes to using Markdown in something like RSS where interop is the primary thing.

But this was one of the first enhancements I wanted to get out there in 2022, the 20th year of RSS 2.0.
