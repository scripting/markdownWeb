Over the years I have been trying to find a magic connection to GitHub. It seems too good a resource to not use in some first class way. Here are a few of my GitHub reading and writing projects.

*   [publishScriptingOpml](https://github.com/scripting/publishScriptingOpml) -- A simple server that copies scripting.com's OPML to the instantOutlines project on GitHub, when pinged.
    
*   [github](https://github.com/scripting/github) -- The source for the [davegithub](https://www.npmjs.com/package/davegithub) package that reads and writes to and from GitHub.
    
*   [oldSchoolNightly](https://github.com/scripting/oldSchoolNightly) -- A script that runs on the same machine as my CMS, that uploads JSON, OPML, RSS and HTML files from Scripting News to the repository on GitHub, every night.
    
*   [githubpub](https://github.com/scripting/githubpub) -- A Node app that serves from GitHub repositories over the web.
    
*   [opmlToGitHub](https://github.com/scripting/opmlToGitHub) -- A Node app that reads an OPML file, converts it to Markdown, and uploads it to GitHub.
    
*   [pagepark](https://github.com/scripting/pagePark) -- My general-purpose Node web server can serve from a GitHub repo. That's how the [xmlrpc.com](http://xmlrpc.com/) and [pagepark.io](http://pagepark.io/) sites work.
    
*   [english](http://this.how/english/) -- An editor that runs in the browser that can create and edit a Markdown document in a GitHub repository.
