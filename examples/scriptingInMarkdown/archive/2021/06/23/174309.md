See the [GitHub thread](https://github.com/scripting/Scripting-News/issues/213) for this post.

I've been building apps on the assumption that if you store something on GitHub, when you get the raw version of that thing, it'll be current. I was getting inconsistent results, so I decided to test that assumption, and it seems that it is _not_ reliable storage.

If you read an object immediately after writing it, you will not always get back what you wrote. It's not just a matter of waiting a second or two, sometimes it's wrong for up to 10 seconds (the delay I programmed into the test).

Here's [the Node app](https://gist.github.com/scripting/6a59532e1a2d1d0a8e6120cf07b9af45) I'm running to test this. It wakes up every minute and saves a file to GitHub with the current local time string. If I reload the [non-raw version](https://github.com/scripting/instantOutlines/blob/main/misc/now.txt) of the page, it usually seems to have the current value. But if I reload the [raw version](https://raw.githubusercontent.com/scripting/instantOutlines/main/misc/now.txt) of the page, it often does not have the correct value.
