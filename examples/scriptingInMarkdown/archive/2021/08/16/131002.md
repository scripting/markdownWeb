Yesterday I wrote a [post](http://scripting.com/2021/08/15.html#a210111) about the mess that opml.org has become, and how I want to start fresh with a well-organized site that points to all the resources available to devs working with OPML, and has lots of room for more.

Today I want to try to unwind one part of the mess.

Here's the situation.

opml.org's DNS is at hover.com.

I've set up the root, [opml.org](http://opml.org/) itself, as an A record pointing to 142.93.4.110. This server is where I host all my simple PagePark sites, ones that consist of static pages, and config.json settings.

When I try to go to opml.org, I am redirected to dev.opml.org.

Why? Until recently opml.org was a bucket on S3, set up to redirect to [dev.opml.org](http://dev.opml.org/).

I'm guessing they used a 301 permanent redirect, which causes my browser to cache the redirect. It doesn't bother making a DNS request for opml.org, because (guessing) the redirect was permanent.

So that's where I am this morning. I want to get opml.org unstuck, and able to be its own site, not to redirect to dev.opml.org, which I'd very much like to retire (and in doing so probably redirecting in the other direction to opml.org).

A [video demo](https://youtu.be/EeiLcLTisBQ) of the problem I hope to solve today.

I'm going to try various things and [put notes here](https://github.com/scripting/Scripting-News/issues/221).

[Poll](https://twitter.com/davewiner/status/1427273264485781511): What do you get when you go to opml.org?

Followup -- we fixed it. Thanks for all the help...

Brent Ashley had exactly the [advice](https://twitter.com/brentashley/status/1427290535480463361) I [needed](https://twitter.com/davewiner/status/1427293487410696195). opml.org problem solved everywhere. I can start with a [fresh slate](http://scripting.com/images/2021/08/16/solved.png). Excellent.
