This is a technical description of a new server bridge between two apps, [PagePark](http://pagepark.io/) and [Little Outliner](http://littleoutliner.com/). It's now possible to view user-editable files through PagePark as long as they've been made public. This is how the pieces fit together.

[PagePark](http://pagepark.io/) is a Node-based HTTP server that has special understanding of two kinds of files -- [Markdown](http://daringfireball.net/projects/markdown/) and [OPML](http://opml.org/).

For Markdown files, it renders them in a template. So you don't have to repeat the envelope for each bit of text, and it's easy to modify, for all pages. So it's a bit of a CMS for Markdown files. It also can connect directly to GitHub repos, so it can serve from them, which is nice because Markdown is a default format on GitHub.

PagePark also has a special ability to render [OPML](http://opml.org/) files. I use this feature for my this.how site which I've been using to accumulate documents that I want to revise over time. Unlike blog posts, they are not ephemeral. Examples include my [Trolling howto](http://this.how/trolls/) and the [Google and HTTP](http://this.how/googleAndHttp/) doc.

So to sum up, what's special about PagePark, for this situation, is that it's really good at rendering OPML documents.

[Little Outliner](http://littleoutliner.com/) is an [outline editor](http://outlinerhowto.opml.org/) that runs in a web browser. Its native format is [OPML](http://opml.org/).

Every file you edit with [LO2](http://littleoutliner.com/) is either public or private.

I have a copy of PagePark running on the same machine as the server that runs Little Outliner. I created a bridge between the two apps, on the server, that allows PagePark to serve from each users' public folder. When you access the page, you'll see a beautifully rendered version, like my this.how documents. Here's an [example](http://my.this.how/davewiner/example.opml).

This might sound complicated, because you've probably never thought of the software that runs these apps. But conceptually it's simple. There's a new bridge between [LO2](http://littleoutliner.com/) and [PagePark](http://pagepark.io/). That bridge is a PagePark plug-in.

I've been talking about the new [plug-in](https://github.com/scripting/pagePark/blob/master/docs/plugins.md) ability for PagePark. I needed that to create this connection. I've designed a lot of plug-in architectures over many years, and this is a good one. All web servers running in JavaScript should consider doing it [this way](https://github.com/scripting/pagePark/blob/master/docs/plugins.md#a-plug-in-is-a-module). The plug-in I use for this bridge, is a bit of logic that translates a URL from the outside, to a file in the user's public folder. I've [published](https://gist.github.com/scripting/a676b0da36c13576877a91fc77a34ecb) the source. As you can see, there's not much there.

To really nail it, it turns this [source file](http://storage2.littleoutliner.com/users/davewiner/myOutlines/example.opml) into this [rendering](http://my.this.how/davewiner/example.opml). That's it. The next step, soon, will be to present a document that explains how to edit and view these files through the new bridge.
