I'm working with [David Beard](https://twitter.com/dabeard) on an experiment. We want to teach editorial organizations how to run their own news "superfeeds," so they can invest in news resources for their editorial people and for their readers. But first we had to do it ourselves, with David in the editorial role and me as his system developer.

In this setup, I'm running [River5](https://github.com/scripting/river5) on my one of my AWS servers. It's generating my news sites, the [NYT river](http://nytimesriver.com/), [podcasts](http://podcatch.com/), [MLB](http://mlbriver.com/), [NBA](http://nbariver.com/), [politics](http://politics.newsriver.org/), [bloggers](http://bloggers.scripting.com/), and the [one](http://scripting.com/river.html) I do for the readers of my blog, and more. We're going to set it up so it generates David's river along with mine.

David needs to create and update a list of feeds for his river. He's not a programmer. I decided to give GitHub a try.

1.  I created a [new repository](https://github.com/scripting/test2) and invited him to be a collaborator.
    
2.  I created a folder called lists, and a file called beard1.txt. I set it up [initially](https://github.com/scripting/test2/commit/fbf356a55a114e730e3076a69b6fdd48e9514923#diff-adaa18d5bfb99074a2656ce71c93dd32) with some of the example feeds included with River5.
    
3.  I told him where the list was, and said he should edit it, to add or remove feeds, and to let me know when it was ready.
    
4.  Then I created a script on the server that reads the [GitHub file](https://github.com/scripting/test2/blob/master/lists/beard1.txt) every five minutes and saves it into the _lists_ folder on my River5 system.
    
5.  From there, [River5](https://github.com/scripting/river5) does what it does with all lists. It creates a new river file, with the same name, and reads all the feeds in the list that it isn't already reading. When an item comes in from a feed he's subscribed to, it's added at the top of his river.
    
6.  Then I created a tiny [HTML shell](http://scripting.com/misc/beardriver/) that uses the [RiverBrowser](https://github.com/scripting/riverBrowser) module to display the river. I pointed it at his [river.js file](http://radio3.io/rivers/beard1.js). It all worked!
    

The most important thing is we have a workflow that allows him to change the contents of his river whenever he wants, without any tech support. That's the kind of system we all like. :boom:
