If I give a variable a short name or all lowercase, then you can bet it's very local.

I thought I had stopped doing this, it came up in one of my talks with Brent last week, but I do still do it. I just did it in fact in some new code I wrote.

And it shows up everywhere.

For example, a string that just appears in a calculation to save time or space, or to make the code more debuggable (I can examine an intermediate value more easily) will probably be called _s_.

A parameter to a callback routine that's used once in the first line of the callback might also be called _s, jsontext_ or _htmltext_. If it was going to be used throughout the callback, or after a few lines of code, it would get a longer or more descriptive name. Probably would still be all lowercase though.

If it's a local declared at the top of a complex function, it would get a camelCase name, to signal to the reader that it's more important, and also to make it possible to search for it. A variable named _s_ would be problematic because there might be more than one in different scopes, not the same variable.
