I got [yesterday's](http://scripting.com/2019/08/08.html) Scripting News looking [pretty good](http://scripting.com/images/2019/08/09/scriptingNewsInEmailSnapshot.png) in email. Learned a lot. Most of the problems were with how HTML email works these days, not Mailchimp. I needed to factor it out to see that. On the other hand they do some stuff that I can't [abide](https://www.youtube.com/watch?v=sYsw0KVRjCM), so this is a necessary exercise. :-)

Caveat: I only tested in Gmail running in Chrome on a Mac. I'm sure other browsers on other machines and other email clients will raise their own kind of hell. :boom:

Some of what I learned:

1.  You can only use standard [web fonts](https://en.wikipedia.org/wiki/Web_typography#Web-safe_fonts). I'm using Arial for everything.
    
2.  You can't include CSS files, all CSS has to be in-line in a <style> element in the <head> section.
    
3.  Styles for <body> are ignored.
    
4.  Don't use lists unless you want their indentation. There appears to be no way to override it. I was using lists, per standard best practices, for stories. I did a hack and replaced all <ul>s and <li>s with divs, and styled them the way I wanted them to look. (This will fuck up deeply nested lists in my stories. Thinking about how to avoid that. Come to think of it, it will probably fuck up this very list. Heh.)
    
5.  I'm using AWS to send the mail, and I'm going to have to do some kind of dance to configure it to let me send email from an address I never use. I can't use my gmail address, because I am not sending the email from gmail. That is a new architecture of the net created by who-the-hell-knows since I last did any programming with email. Not saying it's bad, it was something I had to learn about. I suspect that it will be a rejiggering of the dance you have to go to get an HTTPS server, why not use the same dance? I will be learning more about this for sure.
