![](https://imgs.scripting.com/2018/05/17/mrNatural.png)Yesterday's [braintrust query](https://github.com/scripting/Scripting-News/issues/127) resolved. Turns out [eval](https://www.w3schools.com/jsref/jsref_eval.asp) in JavaScript is tricky re catching errors within a [try](https://www.w3schools.com/js/js_errors.asp). If the code being eval'd makes an asynchronous call, errors in the callback won't be caught by the try, and the app that made the eval call crashes, [in this case](https://github.com/scripting/Scripting-News/issues/127#issuecomment-524656665), [PagePark](https://github.com/scripting/pagepark). The problem was introduced by a new version of Node where the callback on [fs.writeFile](https://www.w3schools.com/nodejs/nodejs_filesystem.asp) is not optional. A confluence of buried problems come to the surface, crashes the server, repeatedly, not sure for what gain. Requiring a callback when none is needed. The tail wagging the dog imho. It creates errors, doesn't prevent them. I never would have made that change to the Node kernel.
