My longtime friend Stan Krute sent an email asking how I do my blog. Rather than do a one-off email, I am going to explain it via blog post, so it's documented publicly.

1.  In the spring of 2017, I wrote a piece of software called [Old School](https://github.com/scripting/oldSchoolBlog). It's a Node.js server app that is configured via a big JSON file. It handles incoming REST-style messages telling it to build blogs that it knows about via the JSON file.
    
2.  I write the blog content with an outliner, and the result is a big OPML file. The server software (Old School) knows where to look for the OPML file, via the config.json file. You can use any outliner to edit the content as long as it produces an OPML file as output.
    
3.  I archive the content of the blog in a [GitHub repository](https://github.com/scripting/Scripting-News/tree/master/blog), so you can see how the content works, going back to May 2017.
    
4.  The <head> elements of the OPML file also configure Old School and it contains information other applications might find useful.
    
5.  Here's a [search](https://duckduckgo.com/?q=site%3Ascripting.com+%22old+school%22&t=h_&ia=web) for Old School on my blog.
    
6.  Even though Old School is undocumented and unsupported, I did provide an [example app](https://github.com/scripting/oldSchoolBlog/tree/master/examples/helloworld). Never know when I will need to install a second instance.
    
7.  The outliner I use is called Electric Outliner. I've never shipped it, and don't have any plans to. I got tired of supporting "products" that few if any people use. This, and Old School were the first two products I made just for myself. It's cool, because the users of the product really respect _the hell_ out of the developer, and the developer knows the users will understand the software even with no docs. :smile:
    
8.  You can use [LO2](http://littleoutliner.com/) -- it's very similar to EO, in fact the core outliner is the same code.
    
9.  If I want to attach a video to a post, I add an attribute called _urlvideo,_ which points to a YouTube file. The runtime of the blog, a browser-based JavaScript app, looks for these attributes when the page is loaded, and builds the necessary structures.
    
10.  Similarly for _urltweet,_ which points to a tweet.
     
11.  If you put an attribute named _flNumberedSubs_ on a headline, Old School generates an <ol> element. _flBulletedSubs_ generates an <ul> element.
     
12.  ![](https://imgs.scripting.com/2017/07/21/trumpHead.png)If you put an attribute named _image_ on an element, its value should be the address of an image, i.e. something that can be put in the src attribute of an <img> element. Old School adds it to the output with a CSS style of float: right. That's how I create right-margin images that I love so much.
     
13.  That reminds me, you can use emoji [short codes](https://www.webfx.com/tools/emoji-cheat-sheet/). :boom:
     
14.  Old School also supports a glossary, a CMS idea that goes back to [Clay Basket](http://scripting.com/clay/whatisclaybasket.html) in [1996](http://scripting.com/clay/claydataglossary.html). It's a simple two-column table represented in an outline. It does string substitutions of the top-level string with its sub-head's value. The glossary I use for Scripting News is also [archived](https://github.com/scripting/Scripting-News/blob/master/blog/misc/glossary.opml) in the repo.
