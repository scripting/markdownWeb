![](https://imgs.scripting.com/2019/10/14/greenAcres.png)Over the weekend I tried out an idea. It's a little Node app that runs on the same server as the [CMS](https://github.com/scripting/oldSchoolBlog) that builds this blog. Every minute it looks at today's posts, for those that have titles (like the post your'e reading now), it checks if it changed, and if so it renders it as Markdown and uploads it to GitHub in a [calendar-based structure](https://github.com/scripting/Scripting-News/tree/master/blog/stories/), along-side all the other [parts](https://github.com/scripting/Scripting-News/tree/master/blog) of the blog I maintain automatically on GitHub. I like using GitHub this way, I have a feeling it'd make a good shared object database.

I've been hand-generating links to the GitHub version to get you all thinking about this idea, like this.

_As an experiment this story is archived [on GitHub](https://github.com/scripting/Scripting-News/blob/master/blog/stories/2019/10/14/a130849.md)._

I did this based on an assumption that I would be able to figure out a way to make it possible for any of my posts to become a sub-project on GitHub. I'm not saying any of them _would_ become projects, only now it would be possible. I thought this might work well with the new [email distribution system](http://scripting.com/email/) which has stimulated so much discussion.

I'm not sure how this is going to work, or if it will work, I'm just trying an idea out. :rocket:
