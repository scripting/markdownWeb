My [little feed reader](https://bsky.app/profile/did:plc:fkwl6tbnev3vdx63bippmscy) on Bluesky is [ready](https://bsky.app/profile/did:plc:oety7qbfx7x6exn2ytrwikmr/post/3lerbu7ugvc2i) for you to follow.

Technically, this is how the pieces fit together.

1.  I'm using the [OPML file](https://viewfeedlist.opml.org/?url=https%3A%2F%2Ffeedland.social%2Fopml%3Fscreenname%3Ddavewiner%26catname%3Dblogroll) for my _blogroll_ category on feedland.social to determine what's posted on Bluesky. When I add or remove feeds from the category, the OPML adjusts dynamically.
    
2.  I'm running a new Node app that has a [websocket](https://javascript.info/websocket) connection to feedland.social. It receives all the new items as they are found from all feeds over the socket. It's feedland.social's [firehose](https://www.pubnub.com/learn/glossary/firehose-api/). Since I'm currently the only user of that server, it's getting news from the all feeds I follow, not just the ones in the blogroll category.
    
3.  The Node app checks each new item to see if it's in one of the feeds in the OPML list. If so, it reformats it to fit in a Bluesky post and sends it to the [feediverse account](https://bsky.app/profile/did:plc:fkwl6tbnev3vdx63bippmscy).
    
4.  If you're subscribed you should see the item, with a link, in your Bluesky timeline.
    

**Notes**.

1.  The Node app re-loads the OPML subscription list every minute so any change is quickly reflected.
    
2.  It's the same [blogroll](https://blogroll.social/) you [see](https://imgs.scripting.com/2024/03/13/expandedBlogScreen.png) on my [blog's home page](http://scripting.com/).
    
3.  The biggest [problem](https://github.com/scripting/textcasting/issues/1) in getting this running was rate-limiting. I have dealt with this on Twitter and other services, but Bluesky was not, for a while, letting anything through with the error message that we were over the limit. It was suggested that we should cache the accessToken rather get a new one for every message. I did that and cautiously turned the server on again at first with a 5 message per hour self-imposed limit, then gradually increased it to 10 per hour. The latest version only requires that there be at least five minutes between posts, so that means no more than 12 per hour.
    
4.  Thanks to [Mark Cuban](https://bsky.app/profile/mcuban.bsky.social/post/3lerhvj52pk27) for the initial idea and his support. He saw a [river of news](https://news.scripting.com/) from [FeedLand](https://docs.feedland.com/gettingstarted.md) and asked if it could work in Bluesky. That was the idea. I have always wanted a tight coupling between Bluesky and [RSS](https://cyber.harvard.edu/rss/rss.html) but didn't know how to do it. We may have just skipped a step.
    
5.  We realllly could use some more formating features in Bluesky messages. This is a really strong use-case imho for the [textcasting](https://textcasting.org/) idea.
    
6.  The coolest thing from my point of view is that I already had all the pieces, fully developed, the only thing that remained was to hook them together.
    
7.  Finally, there's a [this.how page](https://this.how/feediverse/bluesky/) for Little Feed Reader. It's purposely brief, but I have put a link to this post on that page.
