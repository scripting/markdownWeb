![](https://s3.amazonaws.com/scripting.com/images/2022/12/15/drummer.png)A [question](https://github.com/scripting/drummerSupport/issues/198) on GitHub: Is OPML the native file format for Drummer? It's better to first [use](https://imgs.scripting.com/2025/04/07/fileformatScreen.png) the product or [read](https://docserver.scripting.com/drummer/about.opml#1633536117000) the docs or [search](https://www.google.com/search?q=What+is+the+native+file+format+for+Drummer%3F&rlz=1C5CHFA_enUS743US747&oq=What+is+the+native+file+format+for+Drummer%3F&aqs=chrome..69i57j0i512i546j0i546i649j69i64.10884j0j4&sourceid=chrome&ie=UTF-8) on web or use an [AI chatbot](https://claude.ai/share/08b9de36-bc41-454b-a21d-e2edcc75d094) before getting humans involved. Anyway, the answer is yes, OPML is the native file format of [Drummer](http://drummer.land/). It's the reason we chose [OPML](http://opml.org/) as the format for RSS reading lists, so we could edit them in a distant [ancestor](http://scripting.com/2021/01/21/141332.html?title=twentyYearsAgoInPodcasting#a154217) of Drummer's whose native file format was also OPML. I tend not to change file formats gratuitously -- it's how you can use different tools to edit your own data. That's a big part of the plan with [WordLand](https://wordland.social/), because the internal file format for drafts is Markdown, you could put any editor alongside that can edit and save text in Markdown, without a glitch. The idea is to create a new platform, editors for WordPress, and have them all interop with each other perfectly from the start. Because WordLand is the first product in this niche, and Markdown is a very safe choice these days (understood to discourage lock-in), I think it's going to be a perfect basis for interop. Learning from past experience and doing it better each time.
