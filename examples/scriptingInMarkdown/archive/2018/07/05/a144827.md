![](https://imgs.scripting.com/2018/07/05/grandpa.png)I love it when I find a bug in four-year-old code. Today, the culprit was a routine called [decodeXml](https://github.com/scripting/utils/blob/master/daveutils.js#L564) in [daveutils](https://www.npmjs.com/package/daveutils). It was decoding four special strings, &lt; &gt;How different things would be if Apple had partnered with Be instead of Next. I would have liked it because the CEO of Be was an outliner guy. Blogging would have found a natural home there. They probably wouldn't have resisted the web as the Jobs Apple did. &amp; and &quot;. But there's a fifth string it wasn't decoding -- &apos;. This showed in an app called [riverToTweets](https://github.com/scripting/riverToTweets), which routes tweets from rivers to Twitter accounts, such as [nyt](https://twitter.com/nyt) and [nbariver](https://twitter.com/nbariver). It would show up with undecoded &apos; strings in tweets. For [example](https://twitter.com/nbariver/status/1014837759322750976). I had seen this for a long time and assumed the problem was deeply buried in a utility I didn't care a lot about, but it turns out it was in code that's included in almost every project I do, including sites such as [Scripting News](http://scripting.com/). It's now fixed and deployed. Not every app has been updated yet to include the fix. These are the best bugs to fix. Ones that have been sitting there for years waiting to cause problems. :boom:
