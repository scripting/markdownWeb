![](https://imgs.scripting.com/2018/06/09/threeStooges.png)One of the things I'm learning is that there is are [problems](https://www.sitepen.com/blog/2007/10/02/xmlrpc-php-dates/) with date-time values in XML-RPC. The question is whether or not the date part of the date-time should have hyphens. The Frontier implementation does not. The [XML-RPC spec](http://xmlrpc.scripting.com/spec.html) says not. But [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) seems to say they must be present. The built-in [JavaScript function](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/toISOString) includes the hyphens. I don't have any other implementations that I can easily check against, so I don't know what offers the most interop with other XML-RPCs. For now I'm [documenting the issue](https://github.com/scripting/xml-rpc/issues/3), and leaving the JavaScript implementation as it is, for now. This means in this area it does not interop with Frontier, in that Frontier will not understand the JavaScript date-time values. Going in the other direction there is no problem, because I've included a workaround.
