Changes to Likes

1.  A new [home page](http://weblikes.org/) to tie all this stuff together and a new domain, weblikes.org.
    
2.  The first [demo app](http://scripting.com/code/nodelikes/client/) is nice, but it was complex. We needed a [Hello World app](http://scripting.com/code/nodelikes/helloworld/), so now there is one. [Source](https://github.com/scripting/likes/tree/master/examples/helloWorld) provided, of course.
    
3.  Now that there are two example apps, the repository needed a new organization. There's now an [examples folder](https://github.com/scripting/likes/tree/master/examples) at the top level, and the [JavaScript API](https://github.com/scripting/likes/tree/master/api) is in its own folder. Code to include it must change as well. This is exemplified in the [examples](https://github.com/scripting/likes/tree/master/examples).
    
4.  New options for the JavaScript API: 1. You can omit the word "likes," as we do on [Scripting News](http://scripting.com/), and 2. Have the Like bits appended instead of prepended. Check out [code](https://github.com/scripting/likes/blob/master/examples/helloWorld/code.js) in the Hello World app to see how they're set.
    
5.  Various CSS edits that allow the environment defaults to rule the rendering of Likes as opposed to having the values hard-coded in the CSS for likes.
    

There were breaking changes in this release. if you've already deployed, sorry. I haven't heard from anyone who has. If you're depending on this toolkit, great. (No sarcasm.) Please provide [feedback](https://github.com/scripting/likes/issues/1) on the changes and make suggestions or just say hi.
