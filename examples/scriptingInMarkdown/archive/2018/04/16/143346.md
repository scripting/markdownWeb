There have been a couple of reports of trouble installing the latest [River5](https://github.com/scripting/river5), both having to do with the [iconv package](https://www.npmjs.com/package/iconv), which is a [relatively new](http://scripting.com/2018/04/08.html) addition to River5. Here's the [latest report](https://github.com/scripting/river5/issues/20#issuecomment-381571359).

I don't know what the problem is, I had no problems installing it on my Mac or on a Linux server.

When I have trouble with NPM, this is what I do:

1.  Delete the node\_modules folder and do an _npm install._
    
2.  If that doesn't work, [clear](https://docs.npmjs.com/troubleshooting/try-clearing-the-npm-cache) NPM's cache, delete the node\_modules folder and do an _npm install._
    

What's unusual about iconv is that it's written in C, and as part of the npm install process it needs to compile it to machine code.

I am anything but an expert in NPM problems, that's why I'm raising a flag [here](http://scripting.com/2018/04/16/143346.html) on Scripting News.

Update: I think [Anton](https://github.com/scripting/river5/issues/21#issuecomment-381623181) got to the bottom of it. Some systems have it set up so that you can't run downloaded stuff without modifying permissions.
